⚠️ ATENÇÃO CRÍTICA - BANCO DE DADOS:
- NUNCA execute `prisma migrate reset` em ambiente com dados reais/usuários
- Este comando APAGA TODOS OS DADOS do banco de dados
- Sempre fazer backup antes de qualquer migração
- Usar `prisma migrate dev` para criar novas migrações sem perder dados
- Em caso de drift, usar `prisma db push` com extremo cuidado
- Testar migrações sempre em ambiente de desenvolvimento primeiro

🔒 CONEXÕES TRAVADAS - LOCKS NO BANCO:
- CONEXÕES "idle in transaction" SEGURAM LOCKS e impedem ALTER TABLE / DDL
- Se o Prisma db push ou scripts DDL travarem sem progresso, pode ser lock no banco
- Para diagnosticar: `node scripts/check-locks.js` (mostra conexões presas)
- Para matar locks: `node scripts/kill-locks.js` (termina conexões idle que estão travando)
- Conexões do servidor backend que ficam "idle in transaction" por dias impedem alterações de schema
- Diretriz: após matar locks, executar imediatamente o script DDL desejado
- ⚠️ O servidor backend PRECISA estar rodando para os testes, mas conexões idle presas por dias devem ser removidas
